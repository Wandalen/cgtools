# Render Stack: d3

Depth-resolved 3D rendering with physically-based light transport. Sibling
of [d2](001_d2.md) — not an extension — because its core invariants
*contradict* d2's: visibility comes from the GPU (depth buffer + OIT), not
from submission order (vs D2-3), and frames are HDR GPU products, not
vector-exportable documents (vs D2-4).

### Scope

- **Purpose**: The d3 stack's identity card — its invariant table, what it renounces, and which crates live in it.
- **Responsibility**: Aggregate the stack's invariants with links to the crate-level instances pinning each; record membership and the sibling boundary with d2.
- **In Scope**: Stack-level identity: invariants, limitations, member crates.
- **Out of Scope**: Each invariant's statement/enforcement detail (the linked crate instances); the engine's pipeline design (see `module/helper/renderer/docs/feature/`).

### Invariant Table

| ID | Invariant | Pinned / evidenced at |
|----|-----------|------------------------|
| D3-1 | 3D transform hierarchy: glTF-shaped node graph with skinning and animation tracks | `module/helper/renderer/src/webgl/` — `node.rs`, `skeleton.rs`, `animation/`, `loaders/gltf.rs` |
| D3-2 | Depth-buffer visibility with order-independent transparency — no CPU draw sorting, ever | [`renderer` invariant/001](../../module/helper/renderer/docs/invariant/001_depth_buffer_visibility_with_oit.md) |
| D3-3 | Perspective projection camera (orthographic not currently present) | `module/helper/renderer/src/webgl/camera.rs` (`perspective_rh_gl`) |
| D3-4 | PBR metallic-roughness material baseline — one shading model for all content | [`renderer` invariant/002](../../module/helper/renderer/docs/invariant/002_pbr_metallic_roughness_baseline.md) |
| D3-5 | HDR-internal, tone-mapped output — linear `RGBA16F` until the final passes | [`renderer` invariant/003](../../module/helper/renderer/docs/invariant/003_hdr_internal_tone_mapped_output.md) |

### Renounced Capabilities

- Vector/document export of frames: output is pixels; there is no SVG-class
  backend and cannot be one without violating D3-2/D3-5.
- Submission-order layering semantics: draw order carries no visibility
  meaning (the exact opposite of d2's D2-3).
- GPU-free operation: the stack requires a real GPU context, including the
  `EXT_color_buffer_float` extension
  ([`renderer` pitfall/001](../../module/helper/renderer/docs/pitfall/001_requires_ext_color_buffer_float.md)).

Content that must cross into a d2 context (e.g. a 3D object inside a 2D
game) crosses as a foundation resource — see
[../pattern/003](../pattern/003_cross_stack_bridge_via_foundation_resources.md)
and `canvas_renderer`.

### Member Crates

| Crate | Layer | Role |
|-------|-------|------|
| `d3_scene` | L4/L5 (reserved) | Blank crate holding the scene-as-script slot; gated on a committed requirement |
| `line_tools` (`::d3` part) | L3-adjacent | 3D line rendering; straddles d2/d3 — classification pending (see ADR-001 consequences) |
| `renderer` | L3 | The stack engine — canonical opaque path on the L1 HAL (`gpu_hal`, WebGPU + WebGL2); legacy `webgl` tree still bound directly to the L0 driver `minwebgl` (accepted violation until strangled) |

Scene model today is glTF itself, consumed through `renderer`'s loaders —
L4 has no dedicated crate yet.
