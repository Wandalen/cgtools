## Unreleased

### Added

- **Chromatic dispersion — §3.6 ( browser-UNTESTED )**: `transmission_dispersion_scale` / `transmission_dispersion_abbe_number` were parsed and ignored; they now reach the shader. The Abbe number measures how *little* a medium disperses, so the glTF `KHR_materials_dispersion` carrier is its normalised reciprocal ( `dispersion = scale * 20 / Vd`, `material::dispersion_from_abbe` ) — crown glass at `Vd = 64` arrives as `0.3125`. Behind `USE_TRANSMISSION_DISPERSION` the refracted tap is taken three times, once per colour channel, at the indices `material::dispersion_iors` spreads around the base one ( red refracted least, blue most; half-spread `( ior - 1 ) * 0.025 * dispersion`, whose `0.025` is the carrier’s `1 / ( 2 * 20 )` and recovers the optical `( n_d - 1 ) / ( 2 Vd )` ). The per-index tap, including its occluder rejection, is factored into `transmissionRefractedUv` so the dispersive and plain paths share one implementation. A thin-walled shell has no refraction offset for the spread to act on, so the define is not emitted there and the three taps never compile in. 8 new native cases.
- **Fuzz ( sheen ) energy conservation ( browser-UNTESTED )**: the fuzz layer used to be *added* on top of the substrate, so a strong fuzz brightened the material instead of redistributing its energy - OpenPBR composes it as `layer( base, fuzz, fuzz_weight )`, i.e. the layer takes what it reflects *from* the base, and the glTF spelling of the same statement is `f = f_fuzz + f_base * ( 1 - max3( fuzz_color ) * E( mu ) )`. The Charlie NDF has no closed-form directional albedo, so the new `loaders::sheen_albedo` integrates `E( mu, alpha )` off-GPU with the *same* Charlie / Ashikhmin pair and the same `0.1` roughness floor the shader evaluates ( deterministic midpoint quadrature, so the table is reproducible ), the `Renderer` uploads and binds it as an RGBA32F LUT at unit 25 ( `sheen_albedo_lut_set`, `USE_SHEEN_ALBEDO` ), and `main.frag` scales the substrate by `1 - max3( fuzz_color ) * E( NoV, alpha )` before adding the lobe. The environment fuzz term is scaled by the same `E`, so what the layer adds under an environment is exactly what the scaling takes away. Native-tested in `tests/sheen_albedo_test.rs` ( 8 cases ). The LUT is optional : a renderer without it keeps the previous additive behaviour.
- **Transmission 3.3b + volumetric absorption §3.4 ( browser-UNTESTED )**: the transmission slice grew the follow-ups registered with 3.3a. The transmission color target is now allocated with a full mip chain and `generate_mipmap`'d after each capture, and the shader reads it through `textureLod` at `log2( size ) * roughness * clamp( 2*ior - 2, 0, 1 )` - a roughness-driven blur instead of a mirror-sharp tap. The captured depth texture is finally sampled : it is linearized through the projection matrix and compared against the fragment's own view-space z, so a refracted tap that lands on an occluder *in front of* the transmissive surface ( or off-screen ) falls back to the un-refracted pixel rather than smearing a foreground object through the glass. Beer-Lambert absorption ( `USE_TRANSMISSION_ABSORPTION` ) evaluates the spec's `mu_t = -ln( transmission_color ) / transmission_depth` over the slab traversal `thickness / |cos|`, with the spec's `transmission_depth = 0` case ( "the interior medium is absent" ) keeping the previous constant-tint behaviour; `USE_TRANSMISSION_THIN_WALLED` compiles the zero-thickness shell variant ( OpenPBR `geometry_thin_walled` ), which has no interior to refract through or absorb in. The transmitted term is additionally weighted by `1 - F( f0, NoV )`, since the reflected share is already carried by the specular/IBL response. The pure math is lifted into `webgl::material` ( `transmission.rs` : `slab_path_length`, `transmittance`, `blur_lod` ) and mirrored in `main.frag`, native-tested in `tests/openpbr_transmission_test.rs` ( 8 cases ); `tests/openpbr_transmission_shader_test.rs` adds the browser gating + GLSL compile cases for all three variants ( written, not yet executed - needs `cargo test --target wasm32-unknown-unknown` + a browser driver ).
- **Transmission pass + refraction ( §3.3a, browser-UNTESTED )**: dedicated render pass - `FramebufferContext` allocates a transmission target ( RGBA16F color + DEPTH24_STENCIL8 depth *texture*, both MSAA-resolved by `transmission_capture()` ) right after the opaque pass; `Renderer` routes weight-gated materials into a new `transmission_draw` pass ( depth test + write on, no blend ) between opaque and WBOIT via the new `Material::transmission_active()` / `transmission_texture_unit()` trait contract ( units 23/24 ). `main.frag` `USE_TRANSMISSION` refracts the view through a thin plate ( enter front / exit back, offset by `transmissionThickness` ), projects the exit point to screen uv and replaces the diffuse response with the tinted scene sample. `OpenPbrSurface` transmission fields now flow through `openpbr_params_from_surface` ( weight / depth / tint carriers, natively tested ); the viewer's USD set scene gained a front glass sphere as the verification asset. Registered follow-ups: roughness blur, depth-guided parallax ( depth captured + bound but not yet sampled ), Beer-Lambert absorption, thin-walled mode.
- **USD scene ingestion ( N3 second slice, browser-untested )**: `usd_scene_analyze` - the full scene pass resolved off-GPU : prim hierarchy with parent links, shading-subtree skipping, visibility/purpose filtering, material-binding resolution with ancestor inheritance ( `MaterialBindingAPI::compute_bound_material` ), `UsdPreviewSurface` -> `UsdMaterialData` channel mapping and the row-vector -> column-major f32 matrix bridge. Thin GL assembly on top : `usd_geometry_create` ( CPU buffers -> VAO at shader slots 0/1/2 ), `usd_material_apply` ( -> `PbrMaterial`, alpha-mode/ior routing ) and `usd_scene_load` ( `Node` graph + shared-material cache -> `Scene` ). **The GL half has not yet run against a real `WebGl2RenderingContext`** - the pure analyze half is covered by 14 native tests in `tests/usd_scene_test.rs` ( now 5 more : hierarchy, shading skip, binding + inheritance, visibility/purpose, matrix conversion ). USD textures ( `UsdUVTexture` ), cameras/lights and the browser fetch-and-feed glue remain open.
- **USD `.mtlx`-bound materials ( N3 third slice, GL half browser-untested )**: a bound `Material` referencing an external `.mtlx` ( the OpenPBR content pattern : `def Material "x" ( prepend references = @./x.mtlx@</…> )`, e.g. OpenPBRShaderPlayground ) now resolves through the native lane of `usd_scene_analyze` — the reference is read from composed `references` metadata, its text fetched via the new `UsdAssetProvider` trait ( implemented by `UsdInMemoryResolver` ), parsed by the N2 `openpbr_surfaces_from_mtlx`, and captured as `UsdMaterialData::surface`. `usd_material_apply` prefers the surface, routing it through `PbrMaterial::openpbr_surface_apply` ( full specular / clearcoat / fuzz / thin-film carriers ). Analyze without a provider still reports the binding and degrades to the neutral default rather than erroring. 4 new native cases in `tests/usd_scene_test.rs` ( 18 total ).
- **USD browser feed + viewer USD mode ( N3 fourth slice, browser-verified )**: `loaders::usd::usd_scene_load_http` - async fetch of a `.usda` root via `gl::file::load`, `.mtlx` reference discovery with the N3-lite `usda_mtlx_references` scanner, sibling fetches resolved against the scene folder, all fed to the new `usd_scene_from_texts` ( synchronous, in-memory-text entry point ). `.mtlx` bytes deliberately never enter the stage's own `ar::Resolver` ( MaterialX is not a USD layer; composition would try to parse it as USDA ) - they ride the separate `UsdAssetProvider` store, mirroring the native-test setup. `gltf_viewer` gained a **USD scene** mode : a procedural icosphere serialized to `.usda` text + the selected embedded `.mtlx`, through the full `loaders::usd` pipeline under the studio rig. All native tests still pass; the GL half was then verified through this mode in the browser ( three runtime-caught bugs fixed, see Fixed ).
- **USD scene ingestion core ( N3 first slice, browser-untested )**: new optional `native-formats` feature ( `openusd` + `openusd-schemas` `geom`/`shade`, pure Rust, compiles for wasm - spike recorded in the adoption plan §2.2 ). `loaders::usd` ships the off-GPU core : `UsdInMemoryResolver` ( an `ar::Resolver` over a `path -> bytes` map, the browser feed for HTTP-fetched `.usda`/`.mtlx`/`.usdz` bytes with no filesystem ), `usd_stage_open`, `usd_mesh_extract` ( `UsdGeomMesh` fan triangulation with vertex/faceVarying/indexed primvar corner resolution for `normals` / `primvars:st` / `primvars:displayColor`, erroring - never panicking - on malformed topology ) and `usd_local_to_world` ( ancestor `Xform` composition ). Native-tested in `tests/usd_scene_test.rs` ( 9 cases, inline `.usda` fixtures served through the resolver ). GL scene assembly and material binding resolve onto this core as the next slice.
- **OpenPBR Surface ingestion (loader stage)**: the glTF loader now reads the scalar/color factors of the `KHR_materials_*` extensions that transport ASWF OpenPBR Surface parameters (`KHR_materials_ior`, `KHR_materials_sheen`, `KHR_materials_transmission`, `KHR_materials_volume`, `KHR_materials_iridescence`, `KHR_materials_emissive_strength`, `KHR_materials_dispersion`, `KHR_materials_diffuse_transmission`) into the new `PbrMaterial::openpbr_params` field (`OpenPbrParams`), via the pure off-GPU `loaders::gltf::material_openpbr_params_read` (native-tested in `gltf_material_extensions_test.rs`). Parsed-and-stored only: the lobes' shader evaluation and texture maps are deferred follow-ups, so rendering behavior is unchanged.
- **OpenPBR Surface shading (opaque path)**: a material carrying any OpenPBR-carrying extension now selects the spec's opaque layered evaluation in `main.frag` behind the `USE_OPENPBR` define — IOR-driven dielectric Fresnel (`specular_ior` → F0), the energy-preserving per-axis `alpha_t`/`alpha_b` mapping plus Smith joint-visibility GGX (per the OpenPBR spec's microfacet model), a fuzz/sheen lobe (`KHR_materials_sheen`, Charlie NDF + Ashikhmin-Premoze visibility, direct + IBL), and KHR_materials_emissive_strength scaling (also enabled on the legacy path). Materials without those extensions keep the legacy glTF metallic-roughness shader unchanged. Refraction (transmission / volume / subsurface), thin-film iridescence, dispersion and the textured lobe carriers remain deferred.
- **MaterialX (`.mtlx`) OpenPBR lane**: the new canonical `OpenPbrSurface` parameter model (full spec parameter set with spec defaults, `material/openpbr_surface.rs`) and the pure, off-GPU `loaders::openpbr_mtlx::openpbr_surfaces_from_mtlx` reader map ASWF `open_pbr_*.mtlx` surfaces onto it — native-tested in `tests/openpbr_mtlx_test.rs` against verbatim `open_pbr_default/gold/glass/velvet.mtlx` fixtures. Reuses the workspace `quick-xml` dependency.
- **glTF → `OpenPbrSurface` bridge**: `openpbr_from_gltf` maps the core `pbrMetallicRoughness` + `KHR_materials_*` scalar carriers (base color/metalness/roughness, specular weight/color/ior/anisotropy, clearcoat, sheen→fuzz, transmission) onto the canonical surface; lobes glTF cannot express keep their spec defaults. Native-tested in `tests/openpbr_gltf_mapping_test.rs`.
- **USD `.usda` → `.mtlx` resolver (N3-lite)**: `loaders::openpbr_usda::usda_mtlx_references` scans `Material` prims for `references = @….mtlx@…` asset pointers (the OpenPBR content pattern, e.g. OpenPBRShaderPlayground) so the N2 `.mtlx` reader can take over; inline/nodegraph USD stays on the future `openusd` Stage reader. Native-tested in `tests/openpbr_usda_test.rs` and verified end-to-end against the real playground `iceCube.usda` + its `.mtlx`.
- **`OpenPbrSurface → PbrMaterial` runtime bridge**: `openpbr_to_runtime` reduces a canonical surface to glTF-shaped runtime factors (base RGBA/metalness/roughness, KHR specular IOR/weight/color, clearcoat→coat, fuzz) and `PbrMaterial::openpbr_surface_apply` applies them through the `USE_OPENPBR` path — the missing direction that lets `.mtlx`/`.usda`-loaded materials actually render. Native-tested in `tests/openpbr_runtime_mapping_test.rs`.
- **Thin-film iridescence (opaque path)**: `USE_OPENPBR_IRIDESCENCE` evaluates the analytic spectral thin-film Fresnel (`evalIridescence`, Airy-derivative with CIE sensitivity fits) and mixes it into `F_s` by the iridescence weight; carries OpenPBR `thin_film_*` through the `KHR_materials_iridescence` carriers. Note the reference model's degenerate case: on a near-perfect mirror substrate ( e.g. metal gold ) the interference terms cancel and the film only lifts `F_s` toward 1 - visible iridescence needs low-reflectance bases.
- **Kulla-Conty multi-scatter energy compensation (direct lights)**: `loaders::kulla_conty` precomputes the directional-albedo LUT `E( mu, roughness )` + row-constant `E_avg( roughness )` ( GGX VNDF importance sampling, native-tested in `kulla_conty_test.rs` ), the `Renderer` uploads/binds it as an RGBA32F texture, and `main.frag` adds `f_ms = (1-Eo)(1-Ei) / ( PI (1-Eavg) ) * Favg * irradiance` per direct light behind `USE_KULLA_CONTY` for `USE_OPENPBR` materials. IBL keeps its existing Fdez-Agera split-sum compensation.
- **Textured lobe carriers (subset, browser-untested)**: `PbrMaterial` gains `sheen_color_texture` / `sheen_roughness_texture` ( `KHR_materials_sheen`, OpenPBR `fuzz_color`/`fuzz_roughness` ) and `iridescence_texture` ( `KHR_materials_iridescence`, `thin_film_weight` ) slots; texture presence alone gates `USE_OPENPBR` / `USE_OPENPBR_IRIDESCENCE`, the loader resolves the `TextureInfo` blocks, and the shader multiplies factors by RGB / A channels ( glTF factor-defaults-to-one semantics ). Fragment sampler units 20-22. The remaining §3.1 carriers ( transmission / thickness / iridescenceThickness / diffuseTransmission textures ) are deferred to the §3.3 transmission pass. Native loader tests in `gltf_material_extensions_test.rs` pass; the browser gating/compile suite `openpbr_lobe_texture_test.rs` is written but not yet executed ( needs `cargo test --target wasm32-unknown-unknown` + a browser driver ).

### Changed

- **`transmission_depth` is an absorption length scale, not a thickness**: `openpbr_params_from_surface` used to map OpenPBR `transmission_depth` onto the glTF `KHR_materials_volume.thicknessFactor` carrier, which the shader consumed as the *geometric* depth of the slab - so an authored absorption distance drove the refraction offset and nothing drove the absorption. The spec defines `transmission_depth` as the distance after which white light becomes `transmission_color` by Beer's law, which is exactly glTF's `attenuationDistance`/`attenuationColor` pair; it now maps there ( `volume_attenuation_distance` ), `volume_thickness_factor` keeps the geometric slab depth, and `geometry_thin_walled` maps to `thicknessFactor = 0`. `OpenPbrParams`' field docs were corrected to match.
- **`specular_ior` decoupled from the OpenPBR surface path**: an `KHR_materials_ior`-only material now raises just `USE_OPENPBR_IOR` ( the IOR-driven F0 swap ) instead of the full `USE_OPENPBR` evaluation; the whole path is reserved for materials carrying OpenPBR-only lobes ( fuzz / thin-film / transmission / ... ).
- **glTF loader OpenPBR params go through the setter**: `materials_create` previously assigned `openpbr_params` directly, bypassing the defines cache - materials whose last define-raising setter ran *before* the assignment compiled without `USE_OPENPBR`. Also applies the glTF rule that a factor omitted while its texture is present defaults to full strength.

- **IBL multiple-scattering energy compensation**: indirect specular now adds the multi-scatter term (`Fms * Ems` weighted by irradiance) on top of the single-scatter prefiltered reflection, matching three.js `computeMultiscattering()`. Without it, rough metals/plastics read as pure mirrors and the overall specular is too dim.
- **Exposure applied uniformly**: `Renderer::set_exposure` now scales the entire lit result in the PBR shader (`color *= exp2( exposure )`) instead of only the IBL contribution. Previously exposure multiplied just the environment term, over-brightening reflections relative to direct lighting.
- **ACES pre-exposure scaling**: the ACES tone mapping pass now divides by `0.6` before the RRT fit, matching three.js `ACESFilmicToneMapping` so identical exposure values produce identical brightness.
- **Shader program caching**: Materials sharing identical shader source code now reuse a single compiled GPU program instead of compiling duplicates. Programs are keyed by `(TypeId, defines_string)` in a `shader_source_registry` — materials of the same concrete Rust type with identical defines always produce the same shader source, so one compiled program is shared across all instances.
- **Draw call grouping**: Opaque and transparent primitives are sorted by program UUID before drawing, minimizing GPU state switches (program binds).
- **Three-phase rendering pipeline**: The render loop is now split into (1) scene traversal & program compilation, (2) per-program uniform uploads (camera, lights, exposure), and (3) sorted draw calls.
- **Material `bind()` contract**: `bind()` is now the single method responsible for activating texture units, uploading texture data, and binding textures. Implementations must call `gl.active_texture()` before each texture bind. The `upload_textures()` trait method has been removed.
- **IBL texture safety**: IBL textures are rebound after every `material.bind()` call, preventing non-IBL materials from accidentally overwriting IBL texture units.
- **Dirty-flag pattern for `needs_update`**: `PbrMaterial::needs_update` is now `Cell<bool>` with interior mutability. The renderer calls `set_needs_update(false)` after uploading uniforms, so `upload_on_state_change()` is skipped on subsequent frames unless the material is explicitly marked dirty via `set_needs_update(true)`.
- **BREAKING**: Renamed `shadow::Light::light_size()` to `shadow::Light::size()`
- Upgraded shadow depth format from `DEPTH_COMPONENT24` to `DEPTH_COMPONENT32F`
- **BREAKING**: Renamed all `get_`-prefixed `Material` trait methods: `get_id` → `id`, `get_name` → `name`, `get_needs_update` → `needs_update`, `get_ibl_base_texture_unit` → `ibl_base_texture_unit`, `get_vertex_shader` → `vertex_shader`, `get_fragment_shader` → `fragment_shader`, `get_defines_str` → `defines_str`, `get_vertex_defines_str` → `vertex_defines_str`, `get_fragment_defines_str` → `fragment_defines_str`, `get_alpha_mode` → `alpha_mode`, `get_cull_mode` → `cull_mode`, `get_front_face` → `front_face`, `get_depth_func` → `depth_func`, `get_color_write_mask` → `color_write_mask`
- **BREAKING**: Renamed `Material::set_compiled()` to `Material::clear_recompile_flag()`
- **BREAKING**: `Material::set_needs_update()` is now a required method (no default no-op implementation)
- **BREAKING**: Renamed `PbrMaterial::get_vertex_defines()` → `vertex_defines()`, `get_fragment_defines()` → `fragment_defines()`
- **BREAKING**: Renamed `Renderer::get_exposure()` → `exposure()`, `get_bloom_radius()` → `bloom_radius()`, `get_bloom_strength()` → `bloom_strength()`, `get_main_texture()` → `main_texture()`
- **BREAKING**: Renamed `GBuffer::get_texture()` → `texture()`
- **BREAKING**: Removed `shader_hash()` from the `Material` trait (dead code, replaced by `(TypeId, defines_str)` cache key)
- **BREAKING**: Asset loaders (`webgl::loaders::gltf::load`, `webgl::loaders::ibl::load`, `webgl::loaders::hdr_texture::load_to_mip_cube` / `load_to_mip_d2`) no longer rely on `mingl::file::load`'s implicit `/static/` prefix. Path arguments are now passed verbatim to the underlying fetch — callers that previously passed bare paths like `"envMap"` must now pass `"static/envMap"` (or any other valid URL / origin-absolute path). Migration mirrors the upstream `mingl` 0.4.0 change.
- **BREAKING**: `Renderer::set_use_emission` now takes a `&WebGl2RenderingContext` as its first parameter (`set_use_emission( &mut self, gl, use_emission )`). The context is needed to lazily allocate the bloom pass and swap framebuffer the first time emission is enabled.

### Fixed

- **`fuzz_weight` was a bare on/off switch**: both glTF-carrier reductions ( `openpbr_to_runtime`, `openpbr_params_from_surface` ) used the weight only as a gate ( `> 1e-3` ) and then passed `fuzz_color` through unscaled, so every weight above zero produced an identical fuzz layer and the authored value did nothing. OpenPBR composes the layer as `layer( base, fuzz, fuzz_weight )` while `KHR_materials_sheen` has no weight of its own and expresses the layer’s reflectivity entirely through `sheenColorFactor`, so the weight now rides in the colour ( clamped to `[ 0, 1 ]`, since that factor is a reflectivity and the albedo scaling paired with it assumes the same bound ). The glTF direction sets `fuzz_weight = 1` on the presence of the extension, so the round trip stays exact. 3 new cases in `tests/openpbr_runtime_mapping_test.rs`.
- **`readBuffer( DEPTH_STENCIL )` raised `INVALID_ENUM` every frame**: the transmission capture selected a read buffer before blitting depth, but `readBuffer` picks the *color* source and accepts only `BACK`, `NONE` or `COLOR_ATTACHMENT<i>`. The depth/stencil blit reads the read-framebuffer's depth attachment implicitly and needs no selection at all, so the call is gone. The blit itself was unaffected - the error was noise in the console, once per captured frame.
- **The refracted ray’s traversal is no longer angle-dependent**: it was the flat-slab `thickness / |cos|`, which has the cosine on the wrong side for anything convex - it lengthens the path towards the silhouette where the real chord shortens, folding the rim across to the far side of the object. Two corrections were implemented and measured before the angle was dropped entirely: the convex chord `thickness * |cos|` ( exact for a sphere of diameter `thickness` ), and on top of it a second refraction at the back surface with a one-step march to the captured scene, which reproduced an analytic two-refraction ball lens to float precision. Both were reverted, because a real ball is a *wide-angle* instrument : at IOR 1.5 a pixel 80% of the way to the silhouette reads the scene 1.6 radii off-axis and one at 98% reads 7.7 radii off, all of it outside the frame - so the outer band of every transmissive object fell back to the un-refracted pixel, i.e. to whatever sits directly behind it, and the band a crystal ball is recognised by is exactly what a screen-space capture cannot supply. The traversal is now the plain thickness, the three.js / glTF-sample-viewer model, which keeps every tap near the object and on-screen and matches what other real-time renderers produce for the same asset. `material::traversal_length` records all three readings and the measurements; recovering the faithful behaviour needs a capture that extends past the frame, not a better formula. `SLAB_MIN_COS` is gone with the division that needed it.
- **The transmissive slab was a fixed 0.5 world units regardless of object size**: OpenPBR has no geometric-thickness parameter, so a `.mtlx` / `.usda` surface authors none and the shader fell back to a constant - which is wrong at every scale but one. In the viewer, which normalises a scene to a unit bounding box, that slab was thicker than the whole scene, so the refracted exit point left the object entirely and the tap landed on unrelated geometry ( the USD set scene showed the cube's unlit face inside the glass sphere ). `transmission_draw` now overrides `transmissionThickness` per draw with the smallest world-space bounding-box extent of the primitive whenever the material authors no thickness - a new `Material::transmission_thickness_authored` tells the two cases apart, and glTF materials carrying `KHR_materials_volume` keep their authored value. Refraction is scale-invariant as a result. The pure reduction is `material::fallback_slab_thickness`, native-tested in `tests/openpbr_transmission_test.rs`, and both it and the adoption plan §3.4 record the thin-walled alternative ( glTF's "no volume extension means no volume" reading ) that was considered and not taken.
- **Transmission painted a bright outline of every foreground object on the glass**: the refracted tap’s occluder rejection compared the *single* nearest depth texel under the tap, but the capture’s colour and depth do not agree at a silhouette - the colour is filtered ( bilinear at level 0, over `2^lod` texels above it, and averaged across MSAA samples by the resolve blit ) while the depth blit is `NEAREST` and takes one sample. A tap sitting just outside a foreground object therefore carried some of that object’s colour under a background depth, passed the test, and drew a dotted fringe tracing every foreground edge seen through the glass ( reported on the viewer’s USD set scene : a green outline of the cube floating inside the glass sphere ). The test now takes the *nearest* depth over a small cross around the tap, whose radius follows the colour tap’s own footprint ( `material::occluder_dilation_texels` : one texel floor, `2^lod` growth, capped at four so the rejected band cannot start eating the refraction ), so the contaminated edge band is rejected as a whole. Native-tested in `tests/openpbr_transmission_test.rs`.
- **Kulla-Conty compensation was weighted by a single average Fresnel**: the direct-light multi-scatter term added back `F_avg * ( 1 - E( mu_o ) )( 1 - E( mu_i ) ) / ( pi ( 1 - E_avg ) )`, but light that survives `n` microfacet bounces has been Fresnel-weighted `n` times - the weight is the sum of that series, `F_avg^2 E_avg / ( 1 - F_avg ( 1 - E_avg ) )`. Weighting by `F_avg` alone both over-brightened the term and washed the tint out of colored rough metals ( a copper came back closer to white than the substrate it scattered off ). Both direct-light call sites now go through `kulla_fms`, mirrored by the pure `loaders::kulla_conty::multi_scatter_fresnel` and pinned by its two limits in `tests/kulla_conty_test.rs` : a perfect mirror returns all the lost energy, a black substrate none. The IBL term keeps its separate Fdez-Agüera split-sum ( registered ).
- **Clearcoat lobe carried its Fresnel factor twice**: `BRDF_Clearcoat` returned `F * D * V * NoL`, and `main()` then mixed that lobe in with `clearcoatFactor * F_Schlick( 0.04, 1, NoV )` as the weight - but `KHR_materials_clearcoat` composes the coat as `mix( base, specular_brdf, weight * F )` over a *Fresnel-free* `specular_brdf` ( D * V ), so the factor belongs to the mix weight alone. Head-on the coat highlight was multiplied by ~0.04 twice and read about 25x too dim, and the direct coat term disagreed with the coat's own IBL term, which never carried a Fresnel factor. The lobe is now `D * V * NoL`.
- **Thin-film interference was evaluated at the shading normal**: both direct-light paths fed `evalIridescence` the `dot( N, V )` cosine instead of `dot( V, H )` - the angle at the microfacet that actually reflects towards the eye, and the cosine used by the Schlick Fresnel the film's reflectance replaces ( the Khronos reference implementation of `KHR_materials_iridescence` uses `VdotH` too ). The interference colors were pinned to the shading normal instead of moving with the highlight on anything rougher than a mirror.
- **Refracted exit ray was bent twice**: `main.frag`'s transmission block refracted out of the back face with the *entry* eta ( `1 / ior` ) again instead of its reciprocal, so the exit direction kept bending towards the normal instead of returning to `-V` as a parallel-sided slab requires - the sampled offset grew with IOR in the wrong direction. A parallel slab only shifts the exit *position*, so the second `refract()` is gone: the tap is taken at `vWorldPos + t_in * slab_path_length( thickness, cos )`.
- **Viewer-generated cubes had mismatched `faceVertexCounts`** : `push_mesh_body` authored all faces as `3` while `cube_attributes` emitted raw quad corners ( 4 per face ), so the fan-triangulation spanned face boundaries - one triangle per quad was correct and its partner's third vertex came from the neighbouring face ( the collapsed-cube symptom in the viewer's USD mode ). The cube is now authored as genuine quads ( `faceVertexCounts = [4;6]`, loader fans them - same path real USD assets take ) and `push_mesh_body` carries an explicit counts/indices consistency assert.
- **USD viewer set-scene generator authored `xformOp:*` as prim metadata** : the generated `.usda` put the `xformOp:translate/rotateXYZ/scale` assignments inside a prim's `( ... )` metadata parens, which the USDA parser rejected at browser runtime ( `want: Punctuation('='), got NamespacedIdentifier("xformOp:translate")` - "Unable to parse prim metadata entry" ). Attributes belong in the prim body `{ ... }`; the generator is fixed and `analyze_parses_viewer_set_scene_layout` now covers the exact emitted layout end to end.
- **USD vertex normals silently downgraded to faceVarying** ( dark icosphere + purple/blue slivers in the viewer's USD mode ): `interpolation_of` read the `interpolation` metadatum via `get_metadata::< String >`, but openusd stores it as a `token` — the cast fails `TypeMismatch` and the old `.ok().flatten()` swallowed that into `None`, so *every* `vertex` primvar fell through to the faceVarying default. Shared-vertex meshes ( e.g. the 2562-vert / 15360-corner icosphere ) then indexed normals by corner, ran off the end of the array and mass-produced `[ 0 , 0 , 0 ]` fallback normals. Now read as `tf::Token` ( plus the `UsdGeomPrimvar::GetInterpolation` `vertex` fallback for the unauthored case ), covered by `tests/usd_scene_test.rs::vertex_interpolated_normals_index_by_face_vertex_indices`.
- **Kulla-Conty gating substring bug**: `Renderer::primitive_register` decided to bind the Kulla-Conty LUT with `defines.contains( "USE_OPENPBR" )`, which substring-matches `USE_OPENPBR_IOR` — an IOR-only material silently got the multi-scatter energy compensation ( visible as gold "turning diffuse-bright" when touching the IOR slider ). Now matches the exact `#define USE_OPENPBR` line.
- **Screen-space pass culling**: all post-processing passes (tonemapping, sRGB, bloom, color-grading, blend, shadow-to-color) and the OIT composite now explicitly call `gl.disable(CULL_FACE)` before drawing the fullscreen triangle. The fullscreen triangle is back-facing from the camera's perspective, so any preceding opaque pass that leaves `CULL_FACE` enabled would silently cull it, producing a black frame.
- **Bloom alpha channel corruption**: `unreal_bloom.frag` now writes `alpha = 0.0` instead of `1.0`. The main framebuffer alpha channel is used to distinguish geometry pixels (alpha `1`) from background (alpha `0`) for tone mapping and subsequent passes. Writing alpha `1` from the additive bloom blit was overwriting that signal.
- Clear-color background is no longer affected by exposure or tone mapping. The main color target is cleared with alpha `0` to mark background pixels (geometry and skybox write alpha `1`), and the tone mapping pass leaves alpha-`0` pixels untouched — mirroring three.js, where the clear color bypasses tone mapping.
- Removed leftover `format!( "static/{}/{}", ... )` in `webgl::loaders::gltf::load`'s texture-Uri branch which, after the `mingl::file::load` semantics change, produced `static/static/<path>` URLs for any glTF with external textures.
- Fixed IBL texture corruption where `upload_textures()` could overwrite IBL texture units because `active_texture` was not reset after `ibl.bind()`.
- Fixed `light_map` texture not being bound in `PbrMaterial::bind()` (was missing from the bind list).
- Fixed texture unit state leak in custom materials (`GemMaterial`, `SurfaceMaterial`) — `upload()` is now called inside `bind()` with explicit `active_texture()` per unit.
- Fixed `AlphaMode::Mask` materials incorrectly routed to WBOIT transparent pass. Mask uses binary alpha cutoff and needs depth writes, which WBOIT disables. Now routed to opaque pass.
- Fixed off-by-one in light upload bounds check (`i > MAX_*_LIGHTS` → `i >= MAX_*_LIGHTS`). Index 8 is out of bounds for shader arrays declared as `lights[8]`.
- Fixed non-deterministic shader cache keys caused by `FxHashMap` iteration order in `rebuild_defines_cache()`. Entries are now sorted alphabetically before building the defines string.
- **BREAKING**: `PbrMaterial` texture fields (`base_color_texture`, `metallic_roughness_texture`, `normal_texture`, `occlusion_texture`, `emissive_texture`, `specular_texture`, `specular_color_texture`, `light_map`) are now private. Use setter methods (e.g. `set_base_color_texture()`) which automatically call `rebuild_defines_cache()`.
